**Niveaux de confiance** (appliqués à chaque entrée) :

| Marque | Signification |
|---|---|
| ● Lu clairement | Nom lu en pleine résolution, ou OCR concordant sur plusieurs images |
| ◐ Lu partiellement | Lecture incomplète ou incertaine sur un mot / une valeur tronquée à l'écran |

## 3. Codes d'industrie BAC — le mécanisme relevé

### 3.1 Au niveau de l'entreprise (onglet « Client » des Détails de souscription)

Structure lue ● (images f_0015–f_0017 de la vidéo « debut soumission ») :

- **Code d'industrie principal** : champ « Code du BAC » + bouton **Rechercher** (répertoire recherchable) + champ **« % des revenus totaux »**.
- **Code(s) d'industrie supplémentaire(s)** : même structure (Code du BAC + % des revenus totaux) ; **2 lignes** visibles.
- Champ associé : **Description des activités de l'assuré** (texte libre).

### 3.2 Au niveau de chaque bâtiment (onglet « Exploitation » du risque Bâtiments)

Structure lue ● (image f_0006 de la vidéo « risque ») :

- **Code d'industrie principal** : Code du BAC + **% des revenus** + **occupation**.
- **Code(s) d'industrie supplémentaire(s)** : 2 lignes (Code du BAC + % des revenus + occupation).

Les codes d'industrie existent donc à **deux niveaux** : entreprise et emplacement/bâtiment.

### 3.3 Ce que le code déclenche (textes lus dans l'aide-souscripteur)

- **Questions additionnelles sectorielles** — texte intégral lu ● : « Les questions additionnelles permettent aux assureurs de coter rapidement, des cotations justes. **Le nombre et le type de questions dépendent du code de l'industrie sélectionné.** » L'onglet « Questions additionnelles » existe dans les Détails de souscription, mais **n'est jamais ouvert** dans la vidéo (contenu inconnu, voir §5).
- **Base de tarification RC** — note lue sur l'onglet Exploitation ● : « La base de calcul varie selon le code de l'industrie du BAC de l'assuré. » L'écran associe au code : recettes brutes annuelles, % Internet, % de sous-traitants, et la répartition géographique **obligatoire** (% Canadien / % E.-U. / % Étranger), plus employés temps plein/partiel, couvert(s) par la CSST, expérience antérieure liée, et le bloc Alcool (alcool vendu sur les lieux Oui/Non ; recettes fractionnées Alcool / Nourriture / Autre).

### 3.4 Codes BAC et types d'entité

L'écran des types d'entité (§2.5) affiche pour chaque type un champ **« Code du BAC »** et une **Description** : le répertoire BAC de Policy Works couvre donc aussi les formes juridiques, pas seulement les industries.

### 3.5 Codes précis relevés

**Aucun.** Dans le cas filmé, les champs « Code du BAC » sont vides à l'écran (aucun code saisi n'est lisible, au niveau entreprise comme au niveau bâtiment). Le catalogue ne contient donc **aucun code d'industrie précis** — seulement le mécanisme. Les codes eux-mêmes devront venir du répertoire BAC ou des documents de Patrick.

- **Métadonnées initiales** : type de transaction initial (« Soumission (courrier) » dans le cas) et langue du dossier.
- **Traçabilité** : conserver la référence du dossier source et du modèle utilisé (la vidéo ne montre pas si Policy Works la journalise — non relevé).

## 5. Lacunes assumées de ce catalogue

Ce catalogue est **partiel par construction** : il ne contient que ce qu'une seule démonstration filmée (un renouvellement de combinée, un seul cas) a laissé voir. À compléter au fil de l'eau avec les formulaires et documents d'assureurs de Patrick.

| Lacune | Pourquoi | Comment la combler plus tard |
|---|---|---|
| **Numéros de formulaires du catalogue : tous illisibles** | Colonne « No de form. » vide ou trop petite dans chaque image ; aucun numéro lu | Formulaires/libellés officiels des assureurs et du BAC fournis par Patrick ; ne jamais deviner un numéro |
| **Catégories jamais explorées : Crime, CYBER, RC compl., XS, Autres, « Pertes de BB »** | Onglets visibles mais jamais ouverts ni défilés dans la vidéo | Mêmes sources : formulaires d'assureurs par ligne (crime, cyber…), demandes réelles de Patrick |
| **Bris d'équipement : 1 seul libellé** (E1, via le tableau) | Onglet non exploré ; seul le libellé du cas filmé est connu | Formulaires bris d'équipement des assureurs |
| **Contenu des « Questions additionnelles » : inconnu** | L'onglet n'est jamais ouvert ; seul le **mécanisme** de déclenchement (code d'industrie BAC) est documenté (§3.3) | Formulaires/questionnaires sectoriels des assureurs et grossistes ; les jeux copropriété (17) et entrepreneur (7) déjà dans l'app restent les seuls jeux réels connus |
| **Aucun code d'industrie BAC précis** | Champs vides dans le cas filmé ; seul le mécanisme est relevé (§3) | Répertoire BAC (membres) ou codes tirés des polices/demandes réelles de Patrick |
| **Liste des appareils de chauffage tronquée** (§2.2) | Défilement non terminé ; suite sous « Radiateur encastré » non filmée | Liste d'un assureur ou de Policy Works à obtenir ; ne pas inventer la fin |
| **Types d'entité tronqués** (§2.5) | Onglet Client en petits caractères, défilement incomplet | Répertoire BAC des types d'entité |
| **Valeurs non relevées** : combustible utilisé, électricité, plomberie, construction du toit, raisons de non-renouvellement/annulation, clauses bénéficiaires, « Complète ou partielle » (rénovations) | Listes jamais ouvertes dans la vidéo | Formulaires d'assureurs ; saisie au fil des dossiers réels |
| **Paramètres de R1 (RC) coupés** | Bas de l'écran du tableau hors champ (« Plafond pour frais médicaux… ») | Libellé RC complet d'un assureur |
| **Aucun libellé d'assureur identifié comme tel** | Le catalogue filmé est celui de Policy Works (générique) ; rien ne dit quel libellé appartient à quel assureur, ni les « versions bonifiées » par assureur | C'est précisément l'apport attendu des formulaires d'assureurs de Patrick : rattacher chaque libellé à son assureur et à sa version (base / bonifiée) |
| **Cas unique filmé** : renouvellement d'une combinée (fabrication alimentaire, 4 emplacements, Intact) | Une seule démonstration ; les parcours « nouvelle affaire » et autres secteurs peuvent mobiliser d'autres libellés | Alimenter le catalogue dossier par dossier |

## 6. Format d'import suggéré (pour la phase de construction)

Pour qu'une phase ultérieure puisse importer ce catalogue tel quel, chaque libellé devrait devenir une ligne avec :

`nom` · `categorie` (Biens / Pertes d'exploitation / Bris d'équipement / Crime / RC / Cyber / RC complémentaire / XS / Autres / Exclusion) · `no_formulaire` (nullable — **jamais deviné**) · `type_formule` (Étendue / Risques désignés / Standard — §2.9) · `variante` (texte libre lu : ex. « formule par sinistre », « Prime fixe », « BAC 04/98 ») · `assureur` (nullable — inconnu à ce stade, sauf annexe §1.9 : Intact) · `parametres` (liste de paramètres propres, ex. §1.2 P9) · `confiance` (● / ◐ / ○) · `source` (vidéo + image).
